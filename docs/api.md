# API Endpoint — Audio DeepFake Detection

This document covers the FastAPI REST endpoint that wraps the trained ensemble model for inference.

---

## Why FastAPI?

The model is a Python object (scikit-learn VotingClassifier serialised with joblib). It needs a Python runtime to load and run. FastAPI is the lightest way to wrap it into an HTTP endpoint — async by default, auto-generates OpenAPI docs, and handles file uploads natively. It's also what I use in production at work (Sixth Energy's deployment tools run on FastAPI + SSE), so it's a known, proven stack.

## Endpoint Design

A single route handles everything:

```
POST /predict
Content-Type: multipart/form-data
Body: file=<audio.wav>

→ 200 OK
{
    "label": "fake",
    "confidence": 0.9412,
    "features_used": [
        "MFCC (40 coefficients)",
        "Spectral Centroid",
        "Spectral Bandwidth",
        "Spectral Rolloff",
        "Zero Crossing Rate",
        "Chroma (12 bins)",
        "RMS Energy",
        "Spectral Contrast (7 bands)"
    ]
}
```

Plus a health check:

```
GET /health

→ 200 OK
{ "status": "ok", "model": "xgboost-lightgbm-ensemble" }
```

## Implementation

```python
import os
import tempfile
import joblib
import numpy as np
from fastapi import FastAPI, UploadFile, File, HTTPException
from extract_features import extract_features

# Load model once at startup — not on every request
MODEL_PATH = "model/ensemble_model.joblib"
model = joblib.load(MODEL_PATH)

app = FastAPI(
    title="Audio DeepFake Detection API",
    description="Classifies audio as real or AI-generated",
    version="1.0.0"
)

@app.get("/health")
def health():
    return {"status": "ok", "model": "xgboost-lightgbm-ensemble"}

@app.post("/predict")
async def predict(file: UploadFile = File(...)):
    if not file.filename.endswith(('.wav', '.mp3', '.flac', '.ogg')):
        raise HTTPException(400, "Unsupported format. Use .wav, .mp3, .flac, or .ogg")

    # Save upload to temp file (librosa needs a file path)
    with tempfile.NamedTemporaryFile(suffix=".wav", delete=False) as tmp:
        content = await file.read()
        tmp.write(content)
        tmp_path = tmp.name

    try:
        # Same extraction pipeline as training
        features = extract_features(tmp_path)
        features = features.reshape(1, -1)

        # Predict with ensemble
        proba = model.predict_proba(features)[0]
        label_idx = np.argmax(proba)
        label = "real" if label_idx == 0 else "fake"
        confidence = float(proba[label_idx])

        return {
            "label": label,
            "confidence": round(confidence, 4),
            "features_used": [
                "MFCC (40 coefficients)",
                "Spectral Centroid",
                "Spectral Bandwidth",
                "Spectral Rolloff",
                "Zero Crossing Rate",
                "Chroma (12 bins)",
                "RMS Energy",
                "Spectral Contrast (7 bands)"
            ]
        }
    finally:
        os.unlink(tmp_path)  # clean up temp file
```

## Key Design Decisions

### Model loaded at startup, not per-request
`joblib.load()` on the ensemble takes ~200ms. Loading it once when the server starts means every `/predict` call only pays for feature extraction + inference (~50–100ms per clip), not model deserialisation.

### Temp file for upload
librosa requires a file path, not a byte stream. The upload is written to a `tempfile`, processed, then deleted in a `finally` block so it's cleaned up even if extraction fails.

### Feature extraction reuse
The `/predict` route calls the exact same `extract_features()` function used during training. This is critical — if the features were computed differently at inference time (different `n_mfcc`, different `sr`, different aggregation), the model would produce garbage results. Same function, same parameters, same output shape.

### Confidence score
Instead of just returning "real" or "fake", the response includes the probability. This lets consumers set their own threshold — a media forensics tool might require >0.99 confidence; a quick screening tool might accept >0.7.

### Supported formats
librosa can decode `.wav`, `.mp3`, `.flac`, and `.ogg` through its `audioread` backend. The endpoint validates the extension before processing.

## Running Locally

```bash
# Started the server
uvicorn app:app --reload --port 8000

# To test with a real audio file
curl -X POST http://localhost:8000/predict \
  -F "file=@test_audio.wav"

# Or open the auto-generated docs
# http://localhost:8000/docs
```

The `/docs` endpoint (auto-generated by FastAPI) provides an interactive Swagger UI where you can upload files and test the endpoint directly in the browser.
